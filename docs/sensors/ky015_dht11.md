## 1. Sensor Overview & Single-Bus Protocol

The **KY-015** module (from 37-in-1 sensor kits) features the distinctive **"blue block"** plastic housing housing a **DHT11** digital temperature and humidity sensor.

> ⚠️ **Kit Envelope Mislabeling Note:**
> In many 37-in-1 sensor kits, the **KY-013** (analog NTC thermistor) and **KY-015** (digital DHT11 "blue block" temp/humidity sensor) are frequently swapped or placed in mislabeled product envelopes. If your sensor module has the blue plastic grid housing with 3 or 4 pins, it is the digital DHT11 (KY-015).

- **Adafruit DHT Library Sketch:** [sketches/ky_015_000/ky_015_000.ino](file:///home/fekerr/src/arduino26/sketches/ky_015_000/ky_015_000.ino)
- **Standalone Bit-Bang Sketch:** [sketches/ky015_dht11/ky015_dht11.ino](file:///home/fekerr/src/arduino26/sketches/ky015_dht11/ky015_dht11.ino)

Unlike standard Maxim/Dallas 1-Wire (`DS18B20`), the DHT11 utilizes a custom single-bus asynchronous protocol:

### Bus Timing & Handshake Sequence

1. **Start Signal (MCU Pull-Down):**
   - MCU pulls the data bus LOW for $\sim 18\text{ ms}$ to trigger a measurement cycle.
2. **Host Release & Pull-Up:**
   - MCU releases line and pulls HIGH for $20\text{--}40\,\mu\text{s}$, then switches pin mode to INPUT.
3. **Sensor Acknowledge (ACK):**
   - DHT11 responds by pulling the line LOW for $80\,\mu\text{s}$, followed by HIGH for $80\,\mu\text{s}$.
4. **Data Bit Stream (40 Bits):**
   - DHT11 streams out 40 bits (5 bytes: Humidity Integer, Humidity Decimal, Temp Integer, Temp Decimal, Checksum).
   - Bit `0`: HIGH pulse duration $\sim 26\text{--}28\,\mu\text{s}$.
   - Bit `1`: HIGH pulse duration $\sim 70\,\mu\text{s}$.

## 2. Implementation Strategies

### Arduino C++ (`Adafruit_DHT` Library)
In C/C++ environments, driver libraries disable interrupts (`noInterrupts()`) during bit polling to prevent clock timing jitter from corrupting edge measurements:

```cpp
#include "DHT.h"
#define DHTPIN 2
#define DHTTYPE DHT11

DHT dht(DHTPIN, DHTTYPE);

void setup() {
  dht.begin();
}
```

### Embedded Rust (`dht-sensor` Crate on `embedded-hal`)
In Rust, the [`dht-sensor`](https://crates.io/crates/dht-sensor) crate provides a `no_std` driver interface built on top of `embedded-hal` GPIO and delay traits:

- **Crate:** `dht-sensor = "0.2"`
- **Usage:**
  ```rust
  use dht_sensor::*;

  // Pass active GPIO pin and system timer delay implementation
  let mut delay = arduino_hal::delay::Delay::new();
  match dht11::Reading::read(&mut delay, &mut pin) {
      Ok(reading) => {
          // reading.temperature, reading.humidity
      }
      Err(e) => { /* Handle timing / checksum fault */ }
  }
  ```
